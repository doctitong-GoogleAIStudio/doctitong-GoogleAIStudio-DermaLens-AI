# DermaLens AI v1.1.8.aab — Google Play readiness
Analyzed 2026-09-17 with bundletool 1.18.1, jarsigner/keytool (Temurin 17), apksigner (tools/).

VERDICT: The bundle itself is technically valid (bundletool validate passes, targetSdk 36,
16 KB-aligned, properly JAR-signed), but there are TWO issues that will very likely cause
the upload to be rejected by Play Console. Fix both before uploading.


## BLOCKERS

### 1. versionCode 123 is a duplicate

  Build                          versionCode   versionName
  -----------------------------  -----------   -----------
  AI Dermatologist v1.0.10       118           1.0.10
  DermaLens AI v1.1.2 (both)     123           1.1.2
  DermaLens AI v1.1.7            121           1.1.7
  DermaLens AI v1.1.8            123           1.1.8

If v1.1.2 (versionCode 123) was ever uploaded to ANY track (internal testing included),
Play will reject 1.1.8 with "Version code 123 has already been used". Version codes are
also going backwards (123 -> 121 -> 123), so the build system is not incrementing them.
The embedded app.config says versionCode: 118, so the manifest value is coming from
somewhere else in the build. Set it explicitly to 124 or higher and rebuild.

### 2. Signing key has changed — three different certificates across builds

  Build                 Certificate                                              SHA-256
  --------------------  -------------------------------------------------------  ------------------
  v1.0.10, v1.1.2       CN=AI Dermatologist v1.0.1, O=Emergent                  46:30:40:EA:3A:91:7C:38:5A:B9:76:5A:E3:97:85:3D:CA:D3:5F:77:2B:52:84:57:4A:AF:BA:46:3F:2C:F5:47
  v1.1.2 new-icon       CN=AI Dermatologist, O=Vicente C. Cavalida Jr. MD        23:F2:EB:7F:7E:DF:D4:23:50:5B:0A:E2:70:49:68:37:5D:D1:3C:94:3B:9D:1E:A7:1D:56:89:9D:22:5A:31:D1
                        (local ai-dermatologist-release.keystore)
  v1.1.7, v1.1.8        CN=DermaLens AI v1.1.4, O=Emergent                      42:5E:9F:E7:20:9E:2D:B1:3F:95:21:78:B3:D5:37:8D:98:F9:44:0C:D4:0A:AD:AB:DE:78:17:B4:FE:EC:B6:A8
                        (new key generated Sep 16, 2026; valid to 2051-09-16)

Play accepts only the upload key registered for the app. Whichever build was accepted
first locked in that key. v1.1.8 is signed with a brand-new Emergent key that differs
from every earlier build. Unless v1.1.7 was already accepted (meaning the 42:5E... key is
the registered one), this upload will fail with "Your Android App Bundle is signed with
the wrong key".

What to do: Play Console -> Setup -> App signing -> compare the UPLOAD KEY CERTIFICATE
fingerprint against the three above. Then either re-sign 1.1.8 with the matching
keystore, or request an upload-key reset (~2 days). The Emergent build server appears to
generate a fresh key each time (v1.0.1, v1.1.4) — pin ONE keystore and use it for every
release.

## SHOULD FIX (not blockers)

1. App label still includes the version: string/app_name = "DermaLens AI v1.1.8".
   This is what users see under the launcher icon. Set expo.name to "DermaLens AI".

2. URL scheme is still "frontend" (Emergent template default) in both expo.scheme and
   the VIEW/BROWSABLE intent-filter. Change to something app-specific (e.g. "dermalens")
   before relying on deep links.

3. 1.1.7 -> 1.1.8 changed only 8 bytes in base/assets/index.android.bundle (the version
   string) plus 1 byte in baseline.prof. Manifest: versionCode 121 -> 123, versionName
   1.1.7 -> 1.1.8. No other code, resources, or native libs changed. If 1.1.8 was meant
   to include other changes, they did not make it into this build.


## CONSOLE-SIDE ITEMS (Play will require these for this app)

  - Health apps declaration (App content -> Health apps) + visible in-app medical
    disclaimer ("not a substitute for professional diagnosis").
  - Data safety: declare Photos collected and shared with a third party (images go to
    Google Gemini via gemini-backend-proxy), plus Health info if analysis results are stored;
    state encryption in transit and deletion mechanism.
  - Privacy policy URL (mandatory with camera + health data).
  - Account deletion: in-app path + web URL, if the app has user accounts.
  - In-app products: configure under Monetize before review (BILLING is declared).
  - Camera: store listing should explain the camera's purpose.
  - New personal developer accounts (created after Nov 2023): closed test with 12+
    testers for 14 days before production access.
